zephrctl

A tiny CLI over a Unix socket. Nothing requires it — hotkeys and the palette cover everything — but it makes scripting and bar integrations one-liners.

Install

just cli
# or by hand:
cp tools/zephrctl /usr/local/bin/ && chmod +x /usr/local/bin/zephrctl

The socket lives at ~/Library/Application Support/Zephr/zephr.sock while Zephr runs. Protocol: one command per line in, one JSON reply per line out — trivially scriptable without the wrapper too.

zephrctl --help asks the running app for its command table, so it cannot list a command Zephr does not accept, or miss one it does.

Reply shapes: an action answers {"ok":true} or {"ok":false,"error":"…"}; a query answers a bare JSON array, or a bare number with --count. zephrctl exits non-zero whenever the reply carries "ok":false, so zephrctl … && next-thing behaves.

A request is one line and its arguments split on spaces, so a value containing a space has to be quoted. zephrctl quotes what it forwards for you; driving the socket by hand, write list-windows --app "com.example.My App", where a backslash escapes the next character inside the quotes.

Filtering and counting

list-windows takes filters, and every list command takes --count. Both exist for the same reason: a status bar re-runs these several times a second, and the answer it usually wants is a single number. Asking the app for it costs one round trip rather than a round trip plus a jq.

FlagEffect
--focusedOnly the focused window
--workspace NOnly windows on workspace N
--display IDOnly windows on that display, by the id list-displays reports
--app BUNDLE_IDOnly that app's windows, matched case-insensitively on the bundle id
--countReply with the number of matches instead of the array
$ zephrctl list-windows --count
5
$ zephrctl list-windows --workspace 3 --count
2
$ zephrctl list-apps
[{"app":"com.google.Chrome","app-name":"Google Chrome","pid":37693,"windows":1},
 {"app":"com.mitchellh.ghostty","app-name":"Ghostty","pid":3207,"windows":2}]

Filters combine, and an unknown flag is an error rather than a filter that silently did nothing. list-apps aggregates exactly the windows list-windows reports, so the two can never disagree.

Which windows count: list-windows and list-apps cover the windows you can switch to, including ones parked on another Space or in native fullscreen. A minimized window, or one belonging to an app hidden with ⌘H, is in neither. The windows total in list-workspaces is narrower still: it counts what that workspace is laying out right now, so a window waiting on another Space is absent there while list-windows still reports it, with the workspace it will come back to.

Version and protocol

$ zephrctl version
{"ok":true,"version":"0.1","build":"1","protocol":1}

protocol is the version of the wire format, not of Zephr. It rises only when a documented field changes meaning or disappears; new commands and new fields are additive and leave it alone. A script that parses these schemas should check it once and decline to guess at a number it has not been taught. Subscribers get the same number on the hello line, so a long-lived stream never needs a second connection to ask.

The event stream

zephrctl subscribe keeps the connection open and emits one JSON object per line:

{"ok":true,"subscribed":true,"protocol":1}
{"event":"workspace_changed","workspace":"3"}
{"event":"focus_changed","app":"com.googlecode.iterm2","title":"zsh","window":"12885"}
{"event":"window_managed","app":"com.apple.Safari","title":"…","window":"30065"}
{"event":"window_unmanaged","app":"com.apple.Safari","window":"30065"}
{"event":"display_changed","displays":"2"}

SketchyBar in two lines

# sketchybarrc — a workspace indicator driven by the stream
zephrctl subscribe | while read -r line; do
  ws=$(echo "$line" | jq -r 'select(.event=="workspace_changed").workspace')
  [ -n "$ws" ] && sketchybar --set zephr label="$ws"
done &

Or skip the stream entirely and use the config callback:

[callbacks]
on-workspace-changed = ["sketchybar --trigger ws_change WS=$ZEPHR_WORKSPACE"]

Recipes

# A window count for a status bar, with no jq in the loop
zephrctl list-windows --count

# The focused window's title
zephrctl list-windows --focused | jq -r '.[0].title // "-"'

# Jump straight to whatever Safari window is anywhere
id=$(zephrctl list-windows --app com.apple.Safari | jq -r '.[0].id // empty')
[ -n "$id" ] && zephrctl focus-window "$id"

# How busy is each display?
zephrctl list-displays | jq -r '.[].id' | while read -r d; do
  printf '%s: %s windows\n' "$d" "$(zephrctl list-windows --display "$d" --count)"
done

# Refuse to run against a wire format this script has not been taught
[ "$(zephrctl version | jq .protocol)" = 1 ] || { echo "unknown zephrctl protocol" >&2; exit 1; }

# Pause tiling while a screen-share app runs
zephrctl pause; open -W /Applications/zoom.us.app; zephrctl resume

# Health check in scripts
zephrctl doctor | jq -e 'all(.status=="pass")' >/dev/null || echo "zephr unhappy"
