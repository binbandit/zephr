Using Zephr

Everything the app does, in the order you'll meet it.

The mental model

Each workspace owns a tree. Windows are the leaves; the branches are containers that split horizontally or vertically. When a new window appears it splits the focused window along its longer edge, so layouts stay sensible with zero effort. Nothing ever reshuffles behind your back: the same action always produces the same result.

Windows that should float, do — dialogs, pickers, non-resizable windows, small utility windows, and anything in the per-app rules. Everything else tiles.

The leader layer

Press ⌥ Space (or whatever you chose). A translucent command strip appears at the bottom of the screen showing what every key does. While it's open, keys act immediately and never leak to the app underneath.

  • The layer is sticky: h h h ⇧L 3 flows as one thought. Close it with esc or the leader again. Prefer one-command-then-close? Set one-shot = true under [keys].
  • ? expands the strip into the full cheat sheet.
  • The menu-bar item shows ◆ while the layer is open — no invisible modes.
  • After you've used the same layer command ten times, the strip shows its direct chord once — the layer teaches you the fast path.

Every frequent command also has a direct ⌃⌥ chord that needs no leader. The defaults never bind bare ⌥, so international typing (⌥e → é) and Emacs bindings survive. Any key can be pointed somewhere else with a [[bind]] block, using the same command names zephrctl takes. See the complete keymap.

Workspaces

  • 1–9 switches; ⇧1–⇧9 sends the focused window along.
  • Back-and-forth: re-press the workspace you're on to bounce to the previous one.
  • Per display: each monitor shows its own active workspace. ⌃⌥` (or leader tab) hops focus between displays; moving a window past the last split at a display edge carries it to the neighboring display.
  • Name workspaces and make one a floating junk drawer in the config. Names show in the menu bar and palette.
  • Inactive workspaces stash their windows off-screen and hide fully-stashed apps, so Mission Control stays clean. Windows are stashed into a bottom corner rather than straight down: macOS clamps how far below a display a window may sit, so "one point past the bottom edge" lands tens of points short and leaves a strip of window showing. Leader w rescues every window to the current workspace if anything ever feels lost.
  • Windows that step out. Minimizing a window, hiding an app with ⌘H, or dragging a window to another native Space all take it out of the layout so its tile closes instead of holding room for something you can't see. It rejoins the workspace it left when it comes back, though not necessarily the same spot in the tree. The three reasons stack: un-minimizing a window whose app is still hidden does not put it back on screen.

Layouts, splits, and sizing

  • s / v pre-select the next split's direction (right / down).
  • Leader space cycles the focused container between tiles and accordion (non-focused windows collapse to slivers at the edges).
  • m toggles monocle: the focused window temporarily fills the workspace.
  • Building structure by hand: g groups the focused window with the next one into a nested container laid out on the other axis; o flips a group between a row and a column; ⇧G ungroups everything, putting every window back at the top level with an equal share. Without g the only way to make a nested group is to open a window with a split pre-selected, which means closing and reopening windows to rearrange them.
  • Resize: leader r enters resize mode - h j k l adjust in 5% steps, ⇧ for 1%. The direction is where the window's far edge goes, so right and down always grow and left and up always shrink, wherever the window sits in the tree. ⌃⌥- / ⌃⌥= shrink and grow the focused window's share of its container directly.
  • = in the layer balances: every tiled container in the workspace goes back to even shares, not just the one you're standing in. Accordion containers keep their ratios, since their geometry comes from which child has focus.
  • Gaps are 8 pt by default and configurable to 0. The focused window gets an accent outline; its color, width, and corner radius are configurable, and it can be turned off.

Floating

  • t toggles the focused window between tiled and floating. Floats keep their frame and sit above the tiles; move them with the focus-move keys (50 pt nudges).
  • Zephr floats the right things automatically: dialogs and sheets, non-resizable windows, windows both narrower than 500 pt and shorter than 350 pt, modals, and a shipped per-app rules list (System Settings, Zoom's floating controls, and friends). Launchers like Raycast and Alfred are ignored entirely.
  • Overlays are not windows. Screen-share control bars, screenshot overlays, reminder popups, and picture-in-picture panels all describe themselves to macOS as ordinary windows with a close button. Zephr checks the window's layer in the window server and refuses anything sitting above the normal one, so a tile never opens where you see a floating bar.
  • Apps with a minimum size are believed, not fought. When an app comes back bigger than the frame it was given on one axis and no smaller on the other, that is the app stating a minimum. Zephr records it (per axis, and only after seeing the same reading twice, since a read-back taken right after a write can be stale) and the solver stops asking for anything smaller. That used to look like a refusal to tile, and it floated ordinary editors.
  • An app that genuinely refuses the frames it is given - same size back, or a window that will not move - is floated after two strikes. Once every window of the app has refused, the rule is written into your config so the fight never happens again on future launches.

Mouse, when you want it

  • Drag to float: dragging a tiled window by its title bar floats it for the drag. Hover another tile and a highlight shows which half you'd drop into; release to re-tile there. Release over nothing and it stays floating.
  • Resize on the gap: the gap between tiles is an invisible resize handle — the cursor changes, drag to move the split.

The palette

⌃⌥P (or leader p) opens a Spotlight-style palette that fuzzy-searches:

  • Windows - app icon, title, workspace badge. Enter focuses it, switching workspace and display as needed. Native-fullscreen windows appear marked ⛶ and are summoned by activating their app; so are windows you have dragged to another Space.
  • Workspaces - jump by number or name. With more than one display, "bring workspace n here" is listed too.
  • Commands - the everyday ones, searchable by name: float, monocle, balance, cycle layout, rescue, next display, close, split, focus and move, workspace float mode, pause. Forgot a key? Type the command. The newer layout and display operations (group, flatten, row ↔ column, send to display, pause this display) are on the keyboard and in zephrctl, but are not in the palette yet.

Displays, docking, and sessions

With more than one display there are four moves you'll want:

  • tab (or ⌃⌥`) - move your focus to the next display.
  • ⇧tab (or ⌃⌥⇧`) - take the focused window with you.
  • d - send this whole workspace to the next display, windows and tree intact.
  • Summon - the opposite of switching: bring a workspace here, to the display you're looking at. 1–9 goes to wherever a workspace already lives and takes your focus with it, which on two displays can feel like it changed the wrong screen. Summon is in the palette, and bindable as summon 3.

Zephr continuously records a profile per display arrangement: which workspace lives on which display, every tree with its split ratios, and every floating frame. Unplug a monitor and workspaces migrate to what's left; plug it back in and everything returns exactly. The same mechanism reassembles your layout after a relaunch or reboot, matching windows by app and title as they reappear.

Profiles are visible (and deletable) in Settings → Profiles.

Pausing

Menu bar → Pause Zephr (also in the palette, or zephrctl pause). Pausing restores every stashed window, unhides apps, and releases the keyboard completely — Zephr goes fully inert for screen sharing, presentations, or games. Resume re-applies the layout. The menu-bar item shows ⏸ while paused.

You can also pause one display: leader ⇧D, the menu's Pause / Resume This Display Only, or zephrctl pause-display. Zephr stops writing frames on that display while the others keep tiling - for the screen you're presenting from, or the one with the game on it. Anything it had stashed off-screen there is brought back first, so pausing can't strand a window. The keyboard stays Zephr's, and hidden apps stay hidden; only a full pause gives those back.

The menu bar item

A quiet glyph plus the current workspace (per display when you have several, e.g. 3·1). The menu holds a workspace switcher per display, rescue, balance, pause - whole-app and this-display-only - config/tutorial/doctor entry points, launch-at-login, and Settings (⌘,). You can hide the icon (menu-bar-icon = false) or add a Dock icon (dock-icon = true).

Settings vs. the config file

Both edit the same file — ~/.config/zephr/config.toml. The Settings window changes only the keys you touch and preserves your comments and formatting; hand-edits hot-reload the moment you save. Zephr is fully usable without ever opening Settings, and fully configurable without ever opening Settings. Full reference.

Quitting and uninstalling

Quitting Zephr returns every window to the exact frame it had before Zephr managed it and unhides everything — no trace left. Uninstall by quitting, deleting the app, and (optionally) removing ~/.config/zephr and ~/Library/Application Support/Zephr.
