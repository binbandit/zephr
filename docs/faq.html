FAQ & troubleshooting

Start with the built-in doctor: menu bar → Run Doctor… (or zephrctl doctor). It checks everything on this page and offers one-click fixes.

I granted Accessibility but Zephr keeps asking / nothing tiles

macOS binds the Accessibility grant to the app's code signature. After an update or a rebuild with a different signature, System Settings still shows the old checkmark — but the running app is refused. This is the single most common issue with every window manager.

Fix: the permission window has a "Reset Stale Permission…" button — click it, then check the box again. By hand:

tccutil reset Accessibility dev.zephr.Zephr

then re-grant in System Settings → Privacy & Security → Accessibility. Zephr detects the grant instantly; nothing to restart. Release builds keep a stable signature, so this is a once-per-signature event, not a routine.

My hotkeys stopped working

  1. Secure Input? A password field or security tool is holding the keyboard — the menu bar shows a warning. The ⌃⌥ chords automatically fall back to system hotkeys; the leader layer resumes when Secure Input ends. Common holders: password prompts left open, some VPNs and password managers.
  2. Paused? The menu-bar item shows ⏸ while paused — Zephr releases the keyboard entirely by design. Menu bar → Resume.
  3. Permission stale? See above — a dead event tap and a refused permission are the same disease. Zephr retries tap creation automatically for 30 seconds after a grant.

A window won't tile / tiles when it shouldn't

  • Dialogs, non-resizable windows, modals, and windows under 500×350 float on purpose. ⌃⌥T overrides any single window; a [[rules]] entry with action = "tile" or "float" makes it permanent (Settings → Rules can write it for you).
  • Apps that refuse the frames Zephr sets (fixed-size windows) are floated automatically after two attempts, and the rule is saved so it's remembered.
  • Native-fullscreen windows are deliberately unmanaged — macOS owns that Space. They're listed in the palette marked ⛶ and re-tile the moment they leave fullscreen.
  • Minimized windows leave the tree and rejoin when restored.

I can't find a window

Two one-keystroke answers: the palette (⌃⌥P) finds any window by name anywhere, and leader w rescues every window to the current workspace. Losing a window permanently is treated as a critical bug — if rescue ever fails you, please file an issue.

Stage Manager

Incompatible by nature — it rearranges windows on its own. Zephr detects it and shows the doctor with a one-click path to Desktop & Dock settings to turn it off.

Can I run Zephr alongside yabai / AeroSpace / Rectangle?

No — two managers will fight over every window. Zephr checks at launch and names any it finds. (Migrating? The importer brings your AeroSpace rules and gaps across.)

Why isn't Zephr on the Mac App Store?

It can't be. Controlling other apps' windows requires the Accessibility API and a keyboard event tap; both are disallowed for sandboxed App Store apps. This is true of every window manager. Zephr ships as a signed, Hardened-Runtime, notarizable app distributed directly.

Why virtual workspaces instead of macOS Spaces?

Apple provides no public API to create, switch, or move windows between Spaces — tools that control Spaces do it by disabling SIP, which Zephr will never ask for. Zephr's workspaces are its own, engineered to be seamless: computed off-screen stashing that adapts to any monitor arrangement, app-hiding so Mission Control stays clean, and a hard never-lose-a-window guarantee. Windows on your other native Spaces are simply left alone.

Will it drain my battery?

It's designed not to: event-driven first, with a reconciliation audit that only runs while things are actually happening (a deep sweep every ~30 s at idle), coalesced timers, and per-app queues at sensible QoS. Idle CPU budget is <0.5%. If you ever see it misbehave in Activity Monitor, that's a bug — report it.

How does multi-monitor work?

Each display shows its own workspace (the menu bar reads e.g. 3·1). Focus and window-moves cross display edges naturally; ⌃⌥` hops displays. Docking and undocking is the signature feature: layouts are recorded per arrangement and restored exactly — see the guide.

Electron apps behave oddly

Chromium/Electron windows misreport geometry unless a specific accessibility flag is toggled around every frame write — Zephr does this automatically. If a specific Electron app still misplaces, add a rule for it and file an issue with the app name.

Uninstalling

  1. Quit Zephr — every window returns to the exact frame it had before Zephr managed it, and hidden apps are unhidden.
  2. Delete Zephr.app.
  3. Optional cleanup: ~/.config/zephr, ~/Library/Application Support/Zephr, and tccutil reset Accessibility dev.zephr.Zephr.

Getting diagnostics for a bug report

zephrctl doctor
log show --predicate 'subsystem == "dev.zephr"' --last 10m --style compact

Include both outputs, your macOS version, and (if window-placement related) your display arrangement.
