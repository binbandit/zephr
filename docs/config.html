Configuration

~/.config/zephr/config.toml — written with commented defaults on first run, hot-reloaded the moment you save. Every value is optional; an empty file is a complete configuration.

  • Syntax errors surface immediately: a typo shows in the menu bar with its line number ("line 7: expected true or false"), and unknown keys get a did-you-mean suggestion. A broken file never takes window management down — Zephr keeps the last good config. An unrecognized leader key name is rejected the same way, naming the keys you can bind. Purely cosmetic values — the focus-border-* keys — warn and fall back to their default instead of holding the file back, so a mistyped color never costs you the other edits in the same save.
  • The Settings window edits this same file, changing only the keys you touch. Comments, ordering, and formatting survive — safe to keep in your dotfiles.

The whole file

# ~/.config/zephr/config.toml — everything optional; these are the defaults.

leader = "alt-space"          # modifiers-key: ctrl/alt/cmd/shift + a key
menu-bar-icon = true          # the status-bar workspace indicator
dock-icon = false             # menu-bar app by default

[layout]
gaps = 8                      # points between windows and screen edges
accordion-padding = 48        # collapsed sliver width in accordion layout
focus-border = true           # accent border on the focused window
focus-border-color = "accent" # "accent", or a hex: "#7AA2F7" / "#7AA2F7CC"
focus-border-width = 2        # outline thickness in points
focus-border-radius = 19      # outline corner radius; 0 for square corners
default = "tiles"             # tiles | accordion for new workspaces

[keys]
preset = "default"            # default | i3 | aerospace | vim
one-shot = false              # close the layer after one command
layer-timeout = 0             # seconds; 0 = layer never times out

[workspaces]
1 = "code"                    # optional names, shown in menu bar & palette
4 = "chat"
float-by-default = [9]        # junk-drawer workspaces: new windows float

[[rules]]
app = "com.apple.systempreferences"
action = "float"              # float | tile | ignore | "workspace N"

[[rules]]
app = "us.zoom.xos"
title = "^zoom floating"      # optional regex on the window title
action = "float"

[[rules]]
app = "com.tinyspeck.slackmacgap"
action = "workspace 4"        # Slack always opens on workspace 4

[callbacks]
on-workspace-changed = []     # shell commands; $ZEPHR_WORKSPACE is set

Top-level keys

KeyDefaultMeaning
leader"alt-space"The leader chord. Hyphen-separated modifiers (ctrl, alt/opt, cmd, shift) ending in a key name (letters, digits, space, tab, grave). At least one of ctrl/alt/cmd is required.
menu-bar-icontrueShow the status-bar item. Turning this and dock-icon off warns you: hotkeys, zephrctl, and this file remain your surfaces.
dock-iconfalseShow a Dock icon.

[layout]

KeyDefaultMeaning
gaps8Points between windows and screen edges (0–100). Sets both inner and outer.
inner-gaps / outer-gaps—Override the two independently.
accordion-padding48Sliver width for collapsed accordion siblings (2–400).
focus-bordertrueDraw an outline on the focused window at all.
focus-border-color"accent""accent" follows your macOS accent color (drawn at 55% opacity, and it keeps following if you change the setting). Otherwise a hex string — #RGB, #RRGGBB, or #RRGGBBAA for alpha — with the # optional and case-insensitive. A hex is drawn exactly as written, so use the AA pair if you want it translucent. Quote it: an unquoted # starts a TOML comment.
focus-border-width2Outline thickness in points (0.5–20). The outline always sits 1 pt outside the window, so a thicker one never covers content.
focus-border-radiussystemThe outline's own corner radius (0–64); 0 gives square corners. Unset, it tracks the system window radius — 19 on macOS 26, 13 before it.
default"tiles"Layout new workspaces start in: tiles or accordion.

[keys]

KeyDefaultMeaning
preset"default"Chord modifiers: default ⌃⌥ · i3 ⌘⌥ · aerospace bare ⌥ (breaks ⌥-typing!) · vim leader-only. Details.
one-shotfalseClose the leader layer after a single command.
layer-timeout0Seconds of layer inactivity before it closes; 0 = never (0–300).

[workspaces]

KeyMeaning
1–9Workspace names, e.g. 4 = "chat". Shown in the menu bar, palette, and zephrctl list-workspaces.
float-by-defaultList of workspaces where new windows float instead of tiling — the junk-drawer pattern, e.g. [9].

[[rules]]

One block per rule; first match wins, and your rules run before Zephr's shipped list. Add them here, in Settings → Rules (which has an "Add Rule for Focused Window" shortcut), or let Zephr learn them: apps that repeatedly refuse tiling get a float rule written automatically.

KeyMeaning
appBundle identifier (required). Find it with osascript -e 'id of app "Slack"'. zephrctl list-windows shows each window's display name (e.g. "Slack"), not its bundle id — don't copy that value into a rule.
titleOptional case-insensitive regex on the window title.
action"float" · "tile" (override a heuristic) · "ignore" (Zephr never touches it) · "workspace N" (windows open on workspace N).

Even without rules, structural heuristics float dialogs, sheets, modals, non-resizable windows, and windows under 500×350 in both dimensions; launchers (Raycast, Alfred, Spotlight) and system chrome are ignored; native-fullscreen windows are left to macOS. Zephr also refuses anything macOS stacks above the ordinary window layer, which covers screen-share control bars, screenshot overlays, picture-in-picture, reminder popups and password panels without needing a rule for each app.

On top of that Zephr ships a small database of per-app rules for the windows those heuristics still get wrong: System Settings, Calculator and the iOS Simulator float; Zoom's screen-share strip and Activity Monitor's inspector float by title; qutebrowser tiles even though it reports itself as a dialog when window.hide_decoration is set. Your own [[rules]] are checked first, so any of it can be overridden - use action = "tile" to undo a float, or "ignore" to have Zephr let go of a window entirely.

[[bind]]

Rebind any key. Add one [[bind]] block per key; they are checked before the preset, so you can override a single key without redefining the rest of the keymap.

[[bind]]
key = "ctrl-alt-b"       # a chord, or "leader b" for the leader layer
command = "balance"
KeyMeaning
keyA chord such as ctrl-alt-b (ctrl/alt/cmd/shift, at least one of the first three), or leader b / leader shift-b for a key inside the leader layer.
commandThe same vocabulary zephrctl speaks — anything you can run from the shell you can bind.

Commands: focus left|down|up|right, move <dir>, resize <dir> [fine], workspace N, send-to-workspace N, summon N, toggle-float, monocle, balance, rescue, close, cycle-layout, flatten, group [dir], layout [row|column], split h|v, float-mode, pause, pause-display, next-display, move-to-display [dir], move-workspace-to-display [dir], shrink, grow.

A chord must carry a modifier: binding a bare letter would swallow that key in every app, which a config file should not be able to do by accident. A binding that cannot be understood is skipped with a warning naming the line, and the rest of the file still applies.

[callbacks]

KeyMeaning
on-workspace-changedShell commands run on every workspace switch with $ZEPHR_WORKSPACE set. Example: ["sketchybar --trigger ws_change WS=$ZEPHR_WORKSPACE"]. For richer integrations use zephrctl subscribe.

Migrating from AeroSpace or Amethyst

Settings → General → Import from AeroSpace / Amethyst (also offered at the end of onboarding when a config is detected). Zephr reads .aerospace.toml — gaps and per-app float/tile rules map directly — and Amethyst's float list, then shows a plain-language report of what mapped and what didn't. AeroSpace keybindings aren't imported: set preset = "aerospace" to keep the ⌥-chord muscle memory instead.
